The SilenceWatch **Laravel package** monitors your scheduled tasks without you declaring anything: it reads the schedule, declares every task with its real cron expression, and sends a heartbeat around every run. It is licensed under Apache 2.0, deliberately, so it can be embedded in any application.

Laravel 12 and 13, PHP 8.2 or later. There is no other dependency.

## Setup

```bash
composer require silencewatch/laravel
```

Create the API key in your project's *Settings › API keys* and give it to the application:

```dotenv
SILENCEWATCH_API_KEY=sw_...
# SILENCEWATCH_URL=https://watch.example.com   # only when you host SilenceWatch yourself
```

That is all: the service provider is discovered by Laravel, and nothing in your schedule changes.

## What it does

The package listens to the events Laravel's scheduler already fires (`ScheduledTaskStarting`, `ScheduledTaskFinished`, `ScheduledTaskFailed`, `ScheduledBackgroundTaskFinished`). Your tasks are not wrapped or changed.

**Declaration.** The first time `schedule:run` runs a task, the whole schedule is declared to `POST /api/v1/checks/sync` in one request, and the ping keys it returns are kept in the cache. The next runs reuse them: the declaration is sent again only when the schedule changed (a deploy), or once a day. `php artisan silencewatch:sync` declares it right away, which suits the end of a deploy script, and lists what is not watched and why.

**Heartbeats.** Around each run:

```text
POST /p/<key>/start                      when the task starts
POST /p/<key>/<exit code>?duration_ms=   when it ends (0 succeeds, anything else fails)
POST /p/<key>/fail?duration_ms=          when it throws
```

A task in the background (`->runInBackground()`) reports its end from the `schedule:finish` process that Laravel starts when it exits, with its exit code.

Each task gets a **stable identity** that ties it to its history across deploys and servers:

| Scheduled with | Key |
| --- | --- |
| `Schedule::command('backup:run --only-db')` | `artisan:backup:run --only-db` |
| `Schedule::exec('/opt/scripts/export.sh')` | `exec:/opt/scripts/export.sh` |
| `Schedule::job(new PruneOrders)` | `call:App\Jobs\PruneOrders` |
| `Schedule::call(...)->name('refresh-rates')` | `call:refresh-rates` |

The name shown in SilenceWatch is the task's `->description()` when it has one. A task that disappears from the schedule is flagged **orphaned**, never deleted.

## Configuration

Environment variables. Publish the configuration file with `php artisan vendor:publish --tag=silencewatch-config` only if you need to compute a value in PHP.

| Variable | Default | |
| --- | --- | --- |
| `SILENCEWATCH_API_KEY` | none | Without one, nothing is sent |
| `SILENCEWATCH_URL` | `https://app.silencewatch.com` | Your own instance when self-hosting |
| `SILENCEWATCH_ENVIRONMENT` | `APP_ENV` | Part of a check's identity |
| `SILENCEWATCH_ENABLED` | `true` | `false` removes everything |
| `SILENCEWATCH_DEFAULT_GRACE` | `300` | Seconds a run may be late before an alert |
| `SILENCEWATCH_REPORT_START` | `true` | `false` to send only the outcome |
| `SILENCEWATCH_TIMEOUT` | `2` | Seconds per request |
| `SILENCEWATCH_PRUNE` | `true` | `false` when several applications share a project and an environment |
| `SILENCEWATCH_CACHE_STORE` | the default store | Where the ping keys are kept between runs |
| `SILENCEWATCH_PER_INSTANCE_TASKS` | none | Tasks watched on each server, see below |
| `SILENCEWATCH_INSTANCE_ID` | none | This server's stable name, for the tasks above |

Tasks limited to some environments (`->environments('production')`) are declared only from those environments. Time zones are the task's own (`->timezone()`), else `app.schedule_timezone`, else `app.timezone`.

<Aside type="tip">
Use **one environment per application**. `SILENCEWATCH_PRUNE` flags as orphaned every check of the project and environment that a declaration leaves out; if several services share both, set it to `false`, or each would orphan the others' checks.
</Aside>

## Several servers

When the scheduler runs on several servers, they all declare the same tasks in the same
environment, so each task is **one check for all of them: it is up while any of them reports
it**.

- A task with **`->onOneServer()`** runs on one server at a time, and the check hears from
  whichever it is. That is the right rule.
- A task **without** it runs on every server. The check stays up while one of them runs it, so a
  server whose scheduler is stuck (its cron entry gone, say) goes unnoticed while another works.
  If the task should run once, add `->onOneServer()`; if it has to run everywhere, read on.

**Tasks that have to run on every server** (clearing a local cache, deleting temporary files) can
be watched on each one:

```dotenv
SILENCEWATCH_PER_INSTANCE_TASKS=artisan:cache:prune-local,exec:*
SILENCEWATCH_INSTANCE_ID=web-1
```

Those tasks are declared in an environment of the server's own, `production.web-1`, so each
server has its own check and one going quiet is seen while the others report. A trailing `*`
matches a prefix; every other task stays shared. A task with `->onOneServer()` is never watched
per server, since one server runs each run: the package says so and keeps it shared. The ping
keys are cached per server, so servers sharing a cache store do not declare again at every run.

`SILENCEWATCH_INSTANCE_ID` has **no default, and must stay the same across restarts and deploys**
(a server's hostname): a name that changes would leave checks behind that nothing reports to,
and they would go down. Without it, the listed tasks are watched as shared, with a warning. When
you remove a server for good, delete its checks.

## Rules it will not break

- **It never fails your task.** Every error is caught; a task that succeeds is never reported to Laravel as failed because of the package.
- **It costs your tasks almost nothing.** PHP has no background thread, so a heartbeat is a request the scheduler waits for, at most `SILENCEWATCH_TIMEOUT`. Once SilenceWatch has not answered, the other tasks of that run do not wait for it again.
- **It degrades silently.** No key, no network, no server: the schedule runs exactly as without the package, and the next run tries again.
- **No dependency** beyond Laravel itself.

## Not watched

Left out of the declaration, and listed by `php artisan silencewatch:sync`:

- **A closure without a name** has no stable identity. Give it `->name('...')`.
- **A task with a condition** (`->between()`, `->unlessBetween()`, `->when()`, `->skip()`): its cron expression says when it *may* run, not when it does, and watching it would raise false alarms. Create its check by hand and ping it yourself with the [ping API](/docs/ping-api/).
- **Nearest-weekday cron expressions** (`15W`), which the server cannot evaluate.

A task scheduled twice is declared from the schedule that fires most often. A queued job (`Schedule::job()`) is reported when it is dispatched to the queue, not when a worker runs it.
